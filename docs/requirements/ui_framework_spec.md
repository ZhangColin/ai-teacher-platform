## 1. 文档说明

### 1.1 目标
定义平台统一的UI框架，确保：
- 所有业务模块共享一致的界面基础
- 界面结构易于扩展，后续功能迭代不会推倒重来
- 支持响应式设计，适配桌面端和移动端

### 1.2 当前迭代说明
- **目标**: 搭建UI框架Demo，数据可写死，仅展示界面结构
- **不涉及**: 具体业务功能实现、数据交互、后端接口
- **重点**: 布局结构、导航体系、视觉风格

## 2. 整体布局结构

### 2.1 三层结构

```
┌─────────────────────────────────────────┐
│         顶部导航栏 (Header)              │
├─────────────────────────────────────────┤
│                                         │
│         主内容区 (Main Content)          │
│                                         │
└─────────────────────────────────────────┘
```

**布局说明**：
- **顶部导航栏**: 固定在上方，包含Logo、大模块切换、用户信息
- **主内容区**: 根据当前大模块显示不同的布局结构
- **无底部栏**: 当前迭代不包含底部栏

### 2.2 主内容区布局类型

不同大模块的主内容区布局可以不同：

- **AI工具模块**: 左侧菜单 + 右侧聊天区域
- **常用工具模块**: 分类 + 卡片网格
- **作品展示模块**: 分类 + 卡片网格

## 3. 顶部导航栏

### 3.1 布局结构

```
┌──────────┬──────────────────────┬──────────┐
│   Logo   │   大模块切换区域      │  用户信息 │
└──────────┴──────────────────────┴──────────┘
```

**布局规则**：
- **左侧**: Logo（点击可返回首页或平台首页）
- **中间**: 大模块切换（AI工具、常用工具、作品展示等）
- **右侧**: 用户信息（头像、用户名等，当前迭代可写死）

### 3.2 大模块切换

**功能意图**：
- 用户通过顶部导航栏切换不同的大模块（AI工具、常用工具、作品展示等）
- 当前激活的模块需要有明确的视觉反馈
- 具体展示方式和视觉样式由UI设计决定，确保美观专业

**模块列表**（当前迭代）：
- AI工具
- 常用工具
- 作品展示

**扩展性**：
- 后续可动态添加新模块，不影响现有布局

## 4. AI工具模块布局

### 4.1 整体结构

```
┌──────────┬──────────────────────────────────┐
│          │                                   │
│  左侧    │        右侧聊天区域                │
│  菜单    │                                   │
│          │                                   │
└──────────┴──────────────────────────────────┘
```

### 4.2 左侧功能导航栏

**布局结构**：
- 固定宽度（具体宽度由UI设计决定）
- 菜单项固定展开显示（当前迭代，不展开不收起）
- 支持向左收起功能：收起后完全隐藏，留出唤出菜单的方式（如侧边按钮）

**菜单层级与交互逻辑**：
- **一级菜单**: 如"文生文"、"文生图"、"文生视频"、"智能体"等
- **二级菜单**: 部分一级菜单下有二级菜单（如"智能体"下包含"提示词向导"、"Lyar"等）
- **点击规则**：
  - 如果一级菜单没有二级菜单，一级菜单可直接点击（功能切换）
  - 如果一级菜单有二级菜单，一级菜单不可点击，只有二级菜单可点击（功能切换）
- **说明**: 这里的"菜单"本质是功能切换入口，如果有更好的表述或展示方式，可以更改

**菜单项状态**：
- 默认状态、悬停状态、选中状态（当前激活的菜单项）
- 具体样式由UI设计决定

**扩展性要求**：
- 当前固定展开，但要确保后续改为"点击展开/收起"时，改动不会很大
- 菜单项支持动态添加，不影响布局结构

### 4.3 右侧聊天区域

**布局结构**（参考Gemini/DeepSeek的聊天界面）：

```
┌──────────────┬──────────────────────────┐
│              │                          │
│  历史对话    │    当前对话区域（中央）    │
│  列表        │  - 顶部：欢迎语          │
│  （左侧）    │  - 中间：对话内容        │
│              │    （用户输入后，        │
│              │     聊天内容在上方）      │
│              │  - 底部：输入框        │
│              │                          │
└──────────────┴──────────────────────────┘
```

**交互说明**：
- **历史对话列表**（左侧侧边栏）:
  - 显示所有历史对话列表
  - 每个对话项显示对话标题或首条消息预览（数据可写死）
  - 点击对话项切换当前对话
  - 支持新建对话功能（顶部有"新建对话"按钮）
- **当前对话区域**（中央主区域）: 
  - 初始状态：显示欢迎语（居中或靠上显示）
  - 用户输入后：对话内容在上方滚动显示，输入框固定在底部
  - 支持多轮对话，消息按时间顺序展示
  - 输入框支持多行输入，Enter发送，Shift+Enter换行
- **预览功能**: 
  - 点击对话中的预览按钮后，当前对话区域分屏
  - 左侧：聊天区域（对话内容 + 输入框，宽度缩小）
  - 右侧：预览区域（显示预览内容，可手动关闭）
  - 关闭预览后恢复单栏布局（当前对话区域恢复全宽）

**实现标准**：
- 完全参考Gemini/DeepSeek等主流大模型聊天界面的交互方式
- 包括消息展示样式、输入框交互、加载状态、错误处理等所有交互细节
- 具体实现细节和后续调整在功能开发时根据实际需求确定

**布局结构**：
```
┌─────────────────────────────────────┐
│           分类导航（顶部）            │
├─────────────────────────────────────┤
│  ┌────┐  ┌────┐  ┌────┐  ┌────┐   │
│  │卡片│  │卡片│  │卡片│  │卡片│   │
│  └────┘  └────┘  └────┘  └────┘   │
│  ┌────┐  ┌────┐  ┌────┐  ┌────┐   │
│  │卡片│  │卡片│  │卡片│  │卡片│   │
│  └────┘  └────┘  └────┘  └────┘   │
```

**布局结构**：

- 分类 + 卡片网格

## 6. 扩展性要求

**核心要求**：
- UI框架定下来后，后续功能迭代不应推倒重来
- 布局结构模块化，各区域独立，便于扩展
- 导航体系可配置，支持动态添加新模块、新菜单项
- 预留常见UI元素的位置（如面包屑、搜索框等），当前不显示但不影响后续添加

## 7. 响应式设计

### 7.1 断点定义

**桌面端**（默认）：
- 完整布局，所有区域正常显示

**平板端**：
- 左侧菜单可自动收起为抽屉式
- 大模块切换可调整为下拉菜单或折叠式

**移动端**：
- 顶部导航栏：Logo和用户信息保留，大模块切换调整为菜单按钮（汉堡菜单）
- 左侧菜单：完全收起为抽屉式，通过按钮触发
- 主内容区：单栏布局，聊天界面适配小屏
- 预览功能：全屏显示或底部抽屉式

### 7.2 响应式要求

**必须支持**：
- 桌面端（≥1024px）：完整布局
- 平板端（768px - 1023px）：布局调整，菜单可收起
- 移动端（<768px）：简化布局，关键功能可用

**设计原则**：
- 移动端优先考虑核心功能可用性
- 次要功能可隐藏或简化
- 交互方式适配触摸操作

## 8. 风格方向

### 8.1 整体风格

**设计方向**：
- **简洁**: 界面元素精简，避免冗余
- **科技感**: 现代科技风格，符合AI工具平台定位
- **美观**: 视觉设计专业，参考Gemini的设计风格

### 8.2 参考标准

**主要参考**：
- Gemini的界面设计风格
- DeepSeek的聊天界面交互

**设计要点**：
- 颜色搭配：简洁、现代
- 字体：清晰易读
- 间距：合理舒适
- 图标：统一风格
- 动效：流畅自然（如有）
