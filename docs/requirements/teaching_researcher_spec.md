# 功能规格说明：多工具集架构扩展

> **需求背景**: 平台需要支持多个工具集模块（如AI工具、教研员），每个工具集使用相同的功能架构，但加载不同的工具配置。  
> **核心原则**: 一次开发，配置复用。新增工具集模块不需要重新开发功能。

---

## 1. 需求概述

### 1.1 当前问题

**现状**：
- 平台只有一个"AI工具"入口
- 用户点击后进入工具宿主界面（工具选择器 + 历史对话 + 对话区 + 预览区）

**问题**：
- 需要添加"教研员"模块，使用与AI工具完全相同的功能
- 未来可能添加更多类似的工具集模块
- 如果每次都重新开发，成本太高

### 1.2 解决方案

**架构扩展**：
支持两种类型的顶部导航模块：
1. **工具集模块**：点击后进入工具宿主界面，加载对应的工具配置
2. **独立页面模块**：点击后跳转到独立页面（如常用工具、作品展示）

**核心价值**：
- 一次开发，配置复用
- 新增工具集模块只需添加配置，不需要开发新功能
- 保持架构简洁，功能可扩展

## 2. 功能设计

### 2.1 顶部导航模块配置

**配置内容**：
顶部导航显示的所有模块（大模块入口）由配置决定，每个模块包含以下配置项：

**配置项说明**：
- **模块名称**：在顶部导航显示的名称（如"AI工具"、"教研员"）
- **模块类型**：
  - `toolset`（工具集）：点击后加载工具配置，使用工具宿主功能
  - `page`（独立页面）：点击后跳转到独立页面
- **配置来源**（仅工具集类型需要）：该工具集的工具配置文件路径
- **跳转位置**（仅独立页面类型需要）：跳转的页面位置
- **模块图标**：在顶部导航显示的图标
- **显示顺序**：模块在导航栏的显示顺序

**配置示例（概念）**：
```yaml
# 顶部导航模块配置示例（具体格式由开发决定）
modules:
  - name: AI工具
    type: toolset
    config_source: configs/tools/ai_tools/
    icon: sparkles
    order: 1
  
  - name: 教研员
    type: toolset
    config_source: configs/tools/teaching_researcher/
    icon: user-group
    order: 2
  
  - name: 常用工具
    type: page
    page_path: /utility-tools
    icon: wrench
    order: 3
  
  - name: 作品展示
    type: page
    page_path: /gallery
    icon: photo
    order: 4
```

### 2.2 工具集模块的加载逻辑

**用户操作流程**：
1. 用户点击顶部导航的某个工具集模块（如"教研员"）
2. 系统识别该模块类型为 `toolset`
3. 系统从该模块的配置来源路径加载工具配置
4. 系统显示工具宿主界面：
   - 左侧：工具选择器（显示该工具集的所有工具）
   - 左侧：历史对话列表（显示当前用户在当前工具集下的对话）
   - 右侧：对话区和预览区
5. 用户使用工具，功能与AI工具完全一致

**数据隔离**：
- 不同工具集的对话数据独立存储
- 用户切换工具集时，历史对话列表自动切换到对应工具集的数据

**关键点**：
- ✅ 功能完全复用，不需要为新工具集开发新功能
- ✅ 界面完全一致，用户体验统一
- ✅ 只需提供工具配置文件，系统自动加载和展示

### 2.3 工具配置增强：系统提示词文件化

**当前问题**：
- 系统提示词直接写在配置文件中
- 当系统提示词内容较大（如上万字）时，配置文件变得臃肿，难以维护

**解决方案**：
工具配置中，系统提示词支持两种配置方式：

**方式1：直接配置（适合内容较短）**
```yaml
system_prompt: "你是一个专业的AI助手..."
```

**方式2：文件路径配置（适合内容较长）**
```yaml
system_prompt_file: "prompts/chinese_researcher.md"
```

**加载逻辑**：
- 如果配置了 `system_prompt_file`，系统从文件路径读取系统提示词内容
- 如果配置了 `system_prompt`，系统直接使用配置的内容
- 优先级：`system_prompt_file` > `system_prompt`

**文件组织**：
- 系统提示词文件统一存放在提示词目录（如 `configs/prompts/`）
- 文件格式：Markdown（`.md`）
- 文件命名：使用工具ID命名（如 `chinese_researcher.md`）

**优势**：
- ✅ 配置文件保持简洁，易于查看所有工具的列表
- ✅ 系统提示词可以单独编辑，使用Markdown编辑器
- ✅ 支持版本控制，便于追踪修改历史
- ✅ 内容再大也不影响配置文件的可读性

## 3. 首批应用：教研员模块

### 3.1 模块配置

**模块定义**：
- 模块名称：教研员
- 模块类型：工具集（`toolset`）
- 配置来源：`configs/tools/teaching_researcher/`
- 模块图标：待定

**说明**：
教研员模块是多工具集架构的第一个应用实例，用于验证架构的可行性。

### 3.2 教研员工具配置

**工具分类**：
教研员按学科分类组织：
- 语文
- 数学
- 英语
- 其他学科...

**工具配置示例（概念）**：
```yaml
# 语文教研员配置示例
tool_id: chinese_researcher_1
name: 王老师 - 小学语文教研员
category: 语文
description: 专注于小学语文阅读与写作教学
icon: book-open
visible: true
system_prompt_file: prompts/chinese_researcher_1.md
welcome_message: 你好！我是王老师，专注于小学语文教学研究。有什么教学问题需要讨论吗？
show_preview: true
type: normal
```

**系统提示词文件**：
- 文件路径：`configs/prompts/chinese_researcher_1.md`
- 文件内容：教研员的角色定义、专业知识、交互原则等（由业务方提供）
- 文件大小：可能上万字

### 3.3 首批验证

**最小验证集**：
- 配置 2 个教研员（语文 × 1、数学 × 1）
- 验证多工具集架构的可行性
- 验证系统提示词文件加载机制

**验证目标**：
- ✅ 用户能在顶部看到"AI工具"和"教研员"两个入口
- ✅ 点击"教研员"后，能看到语文和数学两个教研员
- ✅ 与教研员对话，功能与AI工具完全一致
- ✅ 系统提示词文件正确加载，教研员回答体现系统提示词的内容
- ✅ 切换工具集时，历史对话列表自动切换

## 4. 技术边界（产品视角）

### 4.1 功能复用范围

**完全复用的功能**：
- 工具选择器（按分类显示工具列表）
- 历史对话列表（按用户+工具维度组织）
- 对话交互（多轮对话、流式响应、输入框等）
- 会话管理（创建、命名、编辑、删除）
- 预览功能（Markdown/HTML/SVG预览和下载）
- 收起/展开功能

**说明**：
工具集模块使用完全相同的功能代码，不需要为新工具集开发新功能。

### 4.2 数据隔离要求

**隔离维度**：
- 按工具集隔离：AI工具的对话数据、教研员的对话数据分别存储
- 按工具隔离：同一工具集内，不同工具的对话数据独立存储
- 按用户隔离：不同用户的对话数据独立存储

**用户体验**：
- 用户切换工具集时，历史对话列表显示该工具集的对话
- 用户切换工具时，历史对话列表显示该工具的对话
- 数据切换自动完成，无需用户手动操作

**首批应用**：

- ✅ 提供对应的系统提示词文件

- ❌ 系统提示词的版本管理界面
