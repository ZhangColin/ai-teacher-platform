## 1. 项目概述

### 1.1 平台定位
一个集成AI能力体验、成果展示和实用工具的综合性平台，旨在：
- 让用户体验多种AI能力（文生文、文生图、AI编程、智能体等）
- 展示AI产生的优质成果（教学案例、编程作品、创意作品）
- 提供AI相关和通用的实用工具

### 1.2 技术架构
- **前端**: Vue 3 + TypeScript + Vite + Tailwind CSS
- **后端**: FastAPI + Python 3.10+
- **AI能力**: 基于大语言模型API（优先Kimi/DeepSeek）

### 1.3 项目现状
- **原有功能**: AI智能备课平台（教案生成、课件生成、图表生成）
- **当前状态**: 原有功能封存，开启全新开发
  - **代码保留**: 旧的备课功能代码保留在 `legacy/` 目录
  - **UI隐藏**: 新版UI中暂不提供原有功能入口，待后续集成
- **复用资源**: 前后端架构、双栏布局组件、多轮对话逻辑

### 1.4 当前阶段目标
- **产出物**: UI设计稿 + 功能模块规划文档
- **实现方式**: 基于设计稿在IDX环境中实现
- **优先级**: 先完成UI设计，再逐个实现功能模块

## 3. MVP范围定义

### 3.1 MVP原则
- **聚焦核心**：只实现AI提示词向导一个完整功能
- **极简展示**：成果展示和工具区仅做基础展示，不做复杂交互
- **渐进迭代**：先把一个功能做好，再逐步扩展
- **避免过度设计**：不要提前开发未明确的功能

### 3.2 第一阶段必做（MVP核心）

#### ⭐ AI提示词向导
**功能描述**：帮助用户将模糊需求转化为清晰、结构化的AI提示词

**必须实现**：
- 左右分屏布局（复用现有ChatLayout组件）
- 多轮对话交互
- 实时生成提示词预览
- 复制和下载功能

**参考对象**：现有教案生成器的交互模式

**详细规格**：见 `ai_prompt_wizard_spec.md`

### 3.3 第一阶段选做（基础展示）

#### 成果展示区
- **范围**: 仅展示静态文件列表
- **交互**: 点击预览、下载
- **数据来源**: 从固定目录读取（无需后端API）
- **暂不实现**: 搜索、筛选、排序、分页

#### 工具区
- **范围**: 展示工具列表卡片
- **交互**: 点击进入工具页（iframe嵌入）
- **暂不实现**: 工具上传、工具管理

### 3.4 明确不做（避免范围蔓延）

**功能层面**：
- ❌ 用户登录/注册
- ❌ 积分体系
- ❌ 权限管理
- ❌ 文生音视频
- ❌ 智能对话（文生文）
- ❌ AI绘图（文生图）
- ❌ AI编程（独立功能，非提示词向导）
- ❌ 社交功能（点赞、收藏、评论、分享）

**技术层面**：
- ❌ 数据库（使用文件系统）
- ❌ 多模型切换（只用Kimi）
- ❌ 用户数据持久化
- ❌ 高级搜索和筛选

**UI层面**：
- ❌ 暗色模式
- ❌ 多语言支持
- ❌ 复杂动效
- ❌ 移动端深度优化（基础适配即可）

## 4. 技术约束说明

### 4.1 大模型选择
- **当前**: Kimi API（或DeepSeek）
- **原因**: 项目已集成，可直接复用
- **未来**: 支持切换多种模型（OpenAI、Claude等）

### 4.2 存储方案
- **当前阶段**: 文件系统存储
  - 成果文件：存放在项目固定目录
  - 工具源码：以HTML单文件形式存储
- **未来规划**: 
  - 引入数据库（MySQL/PostgreSQL）
  - OSS对象存储（阿里云/AWS S3）

### 4.3 前端路由
- **决策方**: UI设计师根据设计稿确定
- **要求**: 清晰的导航结构，良好的用户体验
- **参考**: SPA单页应用，Vue Router管理

### 4.4 系统提示词
- **预设场景**: 每个AI能力模块预设优化的系统提示词
- **用户透明**: 用户无需了解提示词细节，直接体验功能
- **可配置**: 后台可调整优化（开发时讨论）

### 4.5 响应式设计
- **优先**: 桌面端体验
- **兼容**: 移动端基础适配
- **优化**: 二期进行移动端深度优化
