## 1. 项目概述

### 1.1 平台定位
本项目旨在打造一个**可扩展的 AI 能力宿主平台**。它不仅仅是一个单一的功能应用，而是一个能够通过配置快速集成、体验和展示各种 AI 工具能力的底座。

### 1.2 核心价值
- **快速集成**：通过编写系统提示词（System Prompt）和简单的配置文件，即可上线新的 AI 工具。
- **一致体验**：所有 AI 工具共享统一的对话交互和成果预览框架。
- **成果沉淀**：自动捕获并展示 AI 生成的结构化成果（如代码、文案、图表）。

## 2. 平台核心架构（配置驱动）

系统采用“宿主 + 插件”的设计模式，不再针对每个功能进行硬编码开发。

### 2.1 工具配置化 (Tool Configuration)
每一个 AI 工具（如：提示词向导、代码助手）都被定义为一个独立配置文件，包含：

**核心配置**：
- **灵魂（Prompt）**：定义其业务逻辑、引导步骤和输出规范（系统提示词）。
- **能力（Capabilities）**：声明其是否支持预览（HTML/SVG）、是否支持导出等。
- **界面（UI Settings）**：决定其在页面上展示的欢迎语、布局方式（是否开启侧边预览栏）。

**工具显示控制**：
- **显示控制字段**：工具配置中增加 `visible` 字段，控制该工具是否在工具选择器中显示
  - `visible: true`：工具显示在工具选择器中，用户可以选择使用
  - `visible: false`：工具不显示在工具选择器中（可用于隐藏开发中的工具）
- **默认值**：如果配置中未指定 `visible` 字段，默认值为 `true`（显示）

**工具类型**：
工具支持两种类型：
- **类型1：正常工具**：点击后进入该工具的对话界面，用户可以与AI进行对话。工具配置中包含系统提示词，定义该工具的业务逻辑。
- **类型2：占位工具**：工具配置中标记为占位类型（如 `type: "placeholder"`）。点击后显示"敬请期待"页面，提示该功能即将上线。用于提前规划工具位置，保持界面完整性。

**工具分类结构**：
- **分类配置**：工具分类结构在工具配置中定义，具体实现方式由开发决定
- **分类展示**：工具选择器按分类组织展示工具，每个分类下有多个工具
- **分类图标**：每个分类配置图标，用于在工具选择器中展示

**工具图标处理**：
- **图标来源**：工具和分类的图标在配置文件中定义
- **图标生成建议**：配置工具时，可以手动让AI生成图标，然后将生成的图标信息保存在配置文件中
- **图标展示**：工具选择器中显示工具和分类的图标，提升视觉识别度

### 2.2 成果物协议 (Artifacts Protocol)
系统能够识别 AI 消息中的 Markdown 代码块，将其作为可预览的成果物。用户点击代码块上的预览按钮后，右侧预览区才会更新显示对应内容。不在代码块中的内容视为普通对话文本，不触发预览。

## 3. 功能模块规划

### 3.1 平台容器层

**工具选择器**：
- **数据来源**：工具选择器的数据来源于工具配置，工具选择器显示的所有工具，均从后端工具配置文件中加载
- **配置加载机制**：沿用现有的工具配置加载接口和机制，工具选择器直接使用该数据源
- **工具切换**：用户点击工具选择器中的工具卡片，切换到该工具。当前激活的工具卡片有明确的视觉反馈（如主色边框、主色背景等）
- **工具切换效果**：切换工具时，右侧主界面切换到该工具的对话界面
- **收起功能**：工具选择器可以收起为浮动图标，用户点击浮动图标可重新展开

**历史对话列表**：
- **作用域定义**：历史对话列表显示**当前用户在当前工具下的所有历史对话**
- **工具切换联动**：用户切换工具时，历史对话列表自动切换为该工具下的对话列表
- **数据隔离**：不同工具之间的对话列表相互独立，互不干扰
- **排序规则**：对话列表按时间倒序排列，**最新的对话在最前面**
- **对话项展示**：每个对话项显示对话标题（会话名称），可以显示对话的首条消息预览或最后一条消息预览（参考 DeepSeek）
- **对话项交互**：
  - 点击对话项，右侧主内容区切换到该对话的聊天记录，默认滚动到聊天记录的最后（最新消息）
  - 鼠标悬停在对话项上时，显示编辑和删除图标
  - 编辑功能：用户点击编辑图标，可以修改对话标题（会话名称）。编辑方式（实时保存或确认按钮）由开发根据实现便利性决定
  - 删除功能：用户点击删除图标，系统弹出二次确认对话框。确认删除后，该对话及其所有消息永久删除，无法恢复
- **新建对话**：历史对话列表顶部有"新建对话"按钮，点击后右侧主内容区切换到新建对话状态（显示欢迎语和输入框）
- **收起功能**：历史对话列表可以收起为浮动图标，用户点击浮动图标可重新展开。当工具选择器和历史对话列表都收起时，两个浮动图标不应相互重叠
- **交互参考**：完全参考 DeepSeek 网页版的历史对话列表交互方式，包括列表布局和样式、对话项的展示方式、交互细节等

**通用对话区**：
- **会话创建时机**：用户进入工具或点击新建对话时，**不立即创建会话**。只有当用户输入第一条消息并提交后，系统才真正创建会话
- **创建前状态**：创建会话前，右侧主内容区显示欢迎语和聊天输入框（居中显示）
- **欢迎语展示**：
  - 欢迎语来源：欢迎语在工具配置中定义（`welcome_message` 字段）
  - 展示时机：用户进入工具时（尚未创建会话）、用户点击新建对话时
  - 展示位置：右侧主内容区中央，聊天输入框上方
  - 展示方式：参考 DeepSeek 的欢迎语展示方式
  - 特殊情况处理：如果系统提示词中的AI自动返回欢迎语，由开发决定如何处理（是否覆盖配置的欢迎语，或两者如何结合）
- **会话自动命名**：会话创建时（用户发送第一条消息后），系统自动为会话命名。命名规则完全参考 DeepSeek 的会话命名规则，具体命名方式（如基于第一条消息的前N个字符，或AI生成标题）由开发参考 DeepSeek 实现
- **对话内容展示**：提供稳定的多轮对话、流式响应展示、历史记录回溯。每个工具拥有独立的会话空间
- **对话交互标准**：对话界面的所有交互细节（消息展示样式、输入框交互、加载状态、错误处理等）完全参考 DeepSeek 网页版
- **会话持久化**：支持刷新页面后对话不丢失，每个工具的会话独立存储。采用前后端协作方式：后端存储会话和消息到数据库，前端通过调用后端API（GET /api/v1/tools/{tool_id}/conversations 和 GET /api/v1/sessions/{session_id}）恢复会话

**动态预览区**：
- **预览触发机制**：用户点击聊天消息中的代码块上的预览按钮，触发预览功能。系统识别消息中的 Markdown 代码块，只有代码块中的内容才能被预览。代码块的语言类型为 `markdown`、`svg`、`html` 时，代码块上显示预览按钮
- **预览界面布局**：点击预览按钮后，聊天界面左右分屏。左侧为聊天记录区域（对话内容 + 输入框，宽度缩小），右侧为预览沙箱区域（显示预览内容）。用户可以手动关闭预览区域，关闭后恢复单栏布局（聊天区域恢复全宽）
- **预览功能按内容类型区分**：
  - **Markdown 内容预览**：预览区渲染 Markdown 内容，提供下载功能（下载为 Markdown 格式文件、Word 文档、PDF 文件）
  - **HTML 内容预览**：预览区渲染 HTML 内容（在沙箱中安全执行），提供操作功能（全屏预览、下载 HTML 文件、截图功能）
  - **SVG 内容预览**：预览区渲染 SVG 内容，提供操作功能（全屏预览、下载 SVG 文件、截图功能）
- **预览功能边界**：上述预览功能为当前迭代的完整范围，如有新的预览功能需求，后续迭代再讨论

### 3.2 预设工具列表（首批）
- ⭐ **AI 提示词向导 (MVP)**：引导用户通过六步法生成专业提示词。
- **AI 网页实验室 (二期)**：实时生成并预览 HTML/CSS/JS 网页。
- **SVG 创作助手 (二期)**：实时生成并渲染可视化图表。

### 3.3 成果展示与工具集
- **成果列表**：展示平台产生的优秀 AI 作品（支持分类预览和下载）。
- **通用工具箱**：集成 AI 编写的单页面小工具（如 Markdown 转换、图片处理）。

## 4. MVP 范围定义

### 4.1 MVP 核心目标
验证“通用工具宿主”架构的可行性，并完整实现第一个标杆工具：**AI 提示词向导**。

### 4.2 第一阶段必做

**工具管理**：
- **工具选择器从工具配置加载数据**：工具选择器显示的所有工具，均从后端工具配置文件中加载
- **工具显示控制**：工具配置中增加 `visible` 字段，控制该工具是否在工具选择器中显示
- **工具类型支持**：支持正常工具和占位工具两种类型
- **工具分类结构配置**：工具分类结构在工具配置中定义，工具选择器按分类组织展示工具

**历史对话列表**：
- **历史对话列表（按用户+工具维度组织）**：历史对话列表显示当前用户在当前工具下的所有历史对话，切换工具时自动切换对话列表
- **历史对话列表交互**：支持编辑对话标题、删除对话、新建对话功能
- **对话列表排序**：对话列表按时间倒序排列，最新的对话在最前面

**会话管理**：
- **会话延迟创建机制**：用户进入工具或点击新建对话时，不立即创建会话。只有当用户输入第一条消息并提交后，系统才真正创建会话
- **会话自动命名**：会话创建时（用户发送第一条消息后），系统自动为会话命名，命名规则参考 DeepSeek
- **欢迎语配置化展示**：欢迎语在工具配置中定义（`welcome_message` 字段），用户进入工具或点击新建对话时展示

**预览功能**：
- **预览功能增强**：Markdown/HTML/SVG 不同内容类型提供不同的预览操作（下载、全屏、截图等）
- **成果物代码块识别**：识别聊天消息中的 Markdown 代码块，提供预览触发入口

**界面交互**：
- **界面收起功能**：工具选择器和历史对话列表都支持收起为浮动图标，收起时图标不重叠
- **对话交互标准**：对话界面的所有交互细节完全参考 DeepSeek 网页版

**工具实现**：
- **提示词向导工具**：完成六步引导提示词的配置与效果调试

### 4.3 明确不做（MVP 阶段）
- ❌ 复杂的权限和用户体系（仅保留基础的用户登录功能）。
- ❌ 数据存储集成（使用本地文件存储）。
- ❌ 移动端深度交互优化。
- ❌ 收起状态持久化（刷新后恢复默认展开状态）。
- ❌ 其他内容类型的预览功能（后续迭代讨论）。
- ❌ 工具图标的自动生成功能（当前手动配置）。
- ❌ 后端会话恢复功能（MVP 阶段前端自行实现会话恢复，后续迭代如需跨设备同步再考虑后端支持）。

## 5. 用户认证模块

### 5.1 功能概述

**核心功能**：
1. **用户登录**：用户通过用户名、邮箱或手机号和密码登录平台
2. **会话管理**：登录后保持登录状态，支持"记住我"选项
3. **访问控制**：未登录用户自动跳转到登录页
4. **临时用户管理**：内部使用的用户列表和创建页面
5. **用户信息**：用户信息包含手机字段和昵称字段（用于显示）

**设计原则**：
- **安全优先**：登录错误统一提示，不泄露具体错误信息
- **用户体验**：登录后返回原访问页面
- **简化流程**：当前迭代仅支持账号密码登录，不涉及注册

### 5.2 登录功能

**登录页面**：
- 独立登录页面，路径为 `/login`
- 页面元素：平台Logo和名称、账号输入框（必填，支持用户名、邮箱或手机号）、密码输入框（必填，输入时隐藏）、"记住我"复选框（可选）、"登录"按钮、错误提示区域（登录失败时显示）
- 页面布局：居中布局，简洁专业，参考平台整体设计风格

**登录验证规则**：
- **账号规则**：必填项，支持三种格式
  - 用户名格式：1-50个字符，字母、数字、下划线、中文字符（如：zhangsan、张三）
  - 邮箱格式：符合邮箱格式规范（如：user@example.com）
  - 手机号格式：11位数字，以1开头（如：13800138000）
- **密码规则**：必填项，最小长度6位
- **登录验证**：系统根据输入格式判断是用户名、邮箱还是手机号，根据账号类型查询用户，验证账号和密码是否匹配。验证失败时统一提示："账号或密码错误"（不区分具体错误原因，安全考虑）

**登录成功处理**：
1. 系统保存登录凭证（Token）
2. 根据"记住我"选项选择存储方式：
   - 勾选"记住我"：保存到本地存储（关闭浏览器后仍有效）
   - 未勾选：保存到会话存储（关闭浏览器后失效）
3. 跳转到原访问页面（如果有），否则跳转到平台首页
4. 更新顶部导航栏的用户信息显示

### 5.3 会话管理

**Token机制**：
- Token作用：标识用户登录状态，后续请求携带Token验证身份
- Token存储：本地存储（localStorage）用于"记住我"，会话存储（sessionStorage）用于普通登录
- Token有效期：由后端控制，前端不处理过期逻辑。当Token过期时，系统自动跳转到登录页

**登录状态检查**：
- 检查时机：页面加载时、页面刷新时、访问需要登录的功能时
- 检查逻辑：系统检查是否存在有效的登录凭证，如果存在且有效，保持登录状态；如果不存在或已过期，跳转到登录页

**退出登录**：
- 退出方式：用户点击顶部导航栏的"退出"按钮（后续迭代实现）。当前迭代：用户可以通过清除浏览器存储手动退出
- 退出操作：清除登录凭证（Token），跳转到登录页

### 5.4 未登录处理

**访问控制**：
- 平台要求：平台所有功能都需要登录后才能使用，未登录用户无法访问任何功能页面
- 处理流程：
  1. 用户访问平台任何页面
  2. 系统检查登录状态
  3. 如果未登录，自动跳转到登录页
  4. 记录原访问页面地址
  5. 登录成功后，跳转回原访问页面

**登录页访问**：
- 用户可以直接输入登录页地址访问
- 如果已登录，系统自动跳转到首页
- 登录页本身不需要登录即可访问，登录成功后自动离开登录页

### 5.5 临时用户管理

**功能说明**：
- 功能定位：临时管理功能，仅内部使用，用于查看用户列表和创建新用户，不对外公开，不配置到公开导航
- 访问路径：`/admin/users`，需要登录后才能访问

**用户列表页面**：
- 展示所有用户列表
- 显示用户基本信息：用户名、邮箱、手机号、创建时间
- 页面布局：表格形式展示用户列表，简洁实用，无需复杂样式

**创建用户功能**：
- 创建方式：在用户列表页面提供"创建用户"按钮，点击后弹出创建表单或跳转到创建页面
- 创建表单字段：用户名（必填）、邮箱（必填，用于登录）、密码（必填，最小6位）、头像（可选，默认使用系统默认头像）
- 创建流程：
  1. 管理员填写用户信息
  2. 系统验证必填项和格式
  3. 验证通过后创建用户
  4. 创建成功后返回用户列表，显示新创建的用户

**访问控制**：
- 需要登录后才能访问（所有登录用户都可以访问）
- 不配置到公开导航，通过直接输入路径访问
- 只要不对外泄露地址，任何环境都可以使用

### 5.6 用户信息字段定义

**基础字段**：
- **用户名**：类型文本，必填，用于登录，必须唯一，1-50个字符，字母、数字、下划线、中文字符
- **昵称**：类型文本，必填否，用于显示，如果未填写则使用用户名显示
- **邮箱**：类型邮箱，必填否，用于登录，如果填写则必须唯一。用户名、邮箱、手机号至少填写一个（用于登录）
- **手机号**：类型手机号，必填否，用于登录，如果填写则必须唯一，格式：11位数字，以1开头（如：13800138000）。用户名、邮箱、手机号至少填写一个（用于登录）
- **密码**：类型密码，必填是（创建时），最小6位，存储时加密
- **头像**：类型图片URL，必填否，默认使用系统默认头像
- **创建时间**：类型时间戳，系统自动生成

### 5.7 边界条件和异常处理

**登录失败**：
- 账号或密码错误：显示统一错误提示"账号或密码错误"
- 账号不存在：显示统一错误提示"账号或密码错误"（安全考虑，不区分具体错误）
- 密码错误：显示统一错误提示"账号或密码错误"

**网络异常**：
- 登录请求失败（网络错误）：显示错误提示"网络错误，请稍后重试"

**Token过期**：
- Token已过期：系统自动跳转到登录页，用户需要重新登录

**表单验证**：
- 邮箱格式不正确：在输入框下方显示提示"请输入正确的邮箱格式"
- 密码长度不足：在输入框下方显示提示"密码至少需要6位"
- 必填项为空：在输入框下方显示提示"此项为必填项"

**创建用户异常**：
- 邮箱已存在：显示错误提示"该邮箱已被使用"
- 创建用户失败（系统错误）：显示错误提示"创建失败，请稍后重试"
