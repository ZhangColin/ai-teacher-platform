## 1. 项目概述

### 1.1 平台定位
本项目旨在打造一个**可扩展的 AI 能力宿主平台**。它不仅仅是一个单一的功能应用，而是一个能够通过配置快速集成、体验和展示各种 AI 智能体（Agent）能力的底座。

### 1.2 核心价值
- **快速集成**：通过编写系统提示词（System Prompt）和简单的配置文件，即可上线新的 AI 工具。
- **一致体验**：所有 AI 工具共享统一的对话交互和成果预览框架。
- **成果沉淀**：自动捕获并展示 AI 生成的结构化成果（如代码、文案、图表）。

---

## 2. 平台核心架构（配置驱动）

系统采用“宿主 + 插件”的设计模式，不再针对每个功能进行硬编码开发。

### 2.1 智能体配置化 (Agent Configuration)
每一个 AI 工具（如：提示词向导、代码助手）都被定义为一个独立配置文件，包含：
- **灵魂（Prompt）**：定义其业务逻辑、引导步骤和输出规范。
- **能力（Capabilities）**：声明其是否支持预览（HTML/SVG）、是否支持导出等。
- **界面（UI Settings）**：决定其在页面上展示的欢迎语、布局方式（是否开启侧边预览栏）。

### 2.2 成果物协议 (Artifacts Protocol)
系统能够识别 AI 消息中的 Markdown 代码块，将其作为可预览的成果物。用户点击代码块上的预览按钮后，右侧预览区才会更新显示对应内容。不在代码块中的内容视为普通对话文本，不触发预览。

---

## 3. 功能模块规划

### 3.1 平台容器层
- **导航系统**：支持动态加载已配置的 Agent 列表。每个 Agent 配置对应一个独立入口，用户通过导航进入不同的 Agent 页面。
- **通用对话区**：提供稳定的多轮对话、流式响应展示、历史记录回溯。每个 Agent 拥有独立的会话空间。
- **动态预览区**：根据当前 Agent 的能力配置，动态开启或关闭的侧边展示栏。

### 3.2 预设 Agent 列表（首批）
- ⭐ **AI 提示词向导 (MVP)**：引导用户通过六步法生成专业提示词。
- **AI 网页实验室 (二期)**：实时生成并预览 HTML/CSS/JS 网页。
- **SVG 创作助手 (二期)**：实时生成并渲染可视化图表。

### 3.3 成果展示与工具集
- **成果列表**：展示平台产生的优秀 AI 作品（支持分类预览和下载）。
- **通用工具箱**：集成 AI 编写的单页面小工具（如 Markdown 转换、图片处理）。

## 4. MVP 范围定义

### 4.1 MVP 核心目标
验证“通用 Agent 宿主”架构的可行性，并完整实现第一个标杆工具：**AI 提示词向导**。

### 4.2 第一阶段必做
- **通用宿主环境**：实现左对话、右预览的基础布局。
- **Agent 配置加载**：支持从配置文件加载 Agent 信息，每个配置对应一个独立入口。
- **Agent 自动初始化**：用户进入 Agent 页面时，系统自动触发 AI 发出欢迎语，引导用户开始对话。
- **会话持久化**：支持刷新页面后对话不丢失，每个 Agent 的会话独立存储。MVP 阶段由前端实现会话恢复逻辑，后端不需要相关功能。
- **成果物代码块识别**：识别聊天消息中的 Markdown 代码块，提供预览触发入口。
- **提示词向导 Agent**：完成六步引导提示词的配置与效果调试。

### 4.3 明确不做（MVP 阶段）
- ❌ 复杂的权限和用户体系（仅保留 UI 占位）。
- ❌ 数据存储集成（使用本地文件存储）。
- ❌ 移动端深度交互优化。
- ❌ 预览区的复杂操作按钮（复制、下载等功能后续迭代）。
- ❌ 后端会话恢复功能（MVP 阶段前端自行实现会话恢复，后续迭代如需跨设备同步再考虑后端支持）。

---

## 5. 产品约束与边界

- **单一模型依赖**：MVP 阶段仅保证在特定大模型（如 {AI_SERVICE_PROVIDER}）下的表现。
- **本地存储**：数据存储在服务器本地，不涉及云端同步。
- **静态成果展示**：成果展示区初期仅通过读取静态目录实现。
