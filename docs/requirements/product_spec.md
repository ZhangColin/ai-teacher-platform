## 1. 项目概述

### 1.1 平台定位
一个集成AI能力体验、成果展示和实用工具的综合性平台，旨在：
- 让用户体验多种AI能力（文生文、文生图、AI编程、智能体等）
- 展示AI产生的优质成果（教学案例、编程作品、创意作品）
- 提供AI相关和通用的实用工具

### 1.2 技术架构
- **前端**: Vue 3 + TypeScript + Vite + Tailwind CSS
- **后端**: FastAPI + Python 3.10+
- **AI能力**: 基于大语言模型API（优先Kimi/DeepSeek）

### 1.3 项目现状
- **原有功能**: AI智能备课平台（教案生成、课件生成、图表生成）
- **当前状态**: 原有功能封存，开启全新开发
  - **代码保留**: 旧的备课功能代码保留在 `legacy/` 目录
  - **UI隐藏**: 新版UI中暂不提供原有功能入口，待后续集成
- **复用资源**: 前后端架构、双栏布局组件、多轮对话逻辑

### 1.4 当前阶段目标
- **产出物**: UI设计稿 + 功能模块规划文档
- **实现方式**: 基于设计稿在IDX环境中实现
- **优先级**: 先完成UI设计，再逐个实现功能模块

## 3. MVP范围定义

### 3.1 MVP原则
- **聚焦核心**：只实现AI提示词向导一个完整功能
- **极简展示**：成果展示和工具区仅做基础展示，不做复杂交互
- **渐进迭代**：先把一个功能做好，再逐步扩展
- **避免过度设计**：不要提前开发未明确的功能

### 3.2 第一阶段必做（MVP核心）

#### ⭐ AI提示词向导
**功能描述**：帮助用户将模糊需求转化为清晰、结构化的AI提示词

**必须实现**：
- 左右分屏布局（复用现有ChatLayout组件）
- 多轮对话交互
- 实时生成提示词预览
- 复制和下载功能

**参考对象**：现有教案生成器的交互模式

**详细规格**：见 `ai_prompt_wizard_spec.md`

### 3.3 第一阶段选做（基础展示）

#### 成果展示区
- **范围**: 仅展示静态文件列表
- **交互**: 点击预览、下载
- **数据来源**: 从固定目录读取（无需后端API）
- **暂不实现**: 搜索、筛选、排序、分页

#### 工具区
- **范围**: 展示工具列表卡片
- **交互**: 点击进入工具页（iframe嵌入）
- **暂不实现**: 工具上传、工具管理

### 3.4 明确不做（避免范围蔓延）

**功能层面**：
- ❌ 用户登录/注册
- ❌ 积分体系
- ❌ 权限管理
- ❌ 文生音视频
- ❌ 智能对话（文生文）
- ❌ AI绘图（文生图）
- ❌ AI编程（独立功能，非提示词向导）
- ❌ 社交功能（点赞、收藏、评论、分享）

**技术层面**：
- ❌ 数据库（使用文件系统）
- ❌ 多模型切换（只用Kimi）
- ❌ 用户数据持久化
- ❌ 高级搜索和筛选

**UI层面**：
- ❌ 暗色模式
- ❌ 多语言支持
- ❌ 复杂动效
- ❌ 移动端深度优化（基础适配即可）

## 4. 约束与边界

### 4.1 MVP约束
- **单一AI服务**: MVP阶段使用单一AI模型，不支持模型切换
- **简化存储**: 使用简单的文件存储方案，无需数据库
- **无用户系统**: 暂不实现用户登录、权限管理
- **桌面优先**: 优先保证桌面端体验，移动端基础适配

### 4.2 内容约束
- **成果展示**: 仅展示预设的示例作品，不支持用户上传
- **工具数量**: 初期工具数量有限，按需逐步扩充
- **系统提示词**: 由产品方预设并优化，用户不可见不可改

### 4.3 性能约束
- **响应时间**: AI提示词生成过程可能需要10-30秒，需合理设置用户预期
- **并发限制**: MVP阶段不考虑高并发场景
