## 需求概述

### 背景
平台已实现用户认证、AI工具、常用工具、作品展示等功能模块。当前缺少统一的后台管理界面，导致内容管理（用户、工具、作品）只能通过数据库或临时页面操作，效率低且易出错。

### 目标
建立统一的后台管理系统，为内部运营人员提供便捷的管理界面，支持用户管理、常用工具管理、作品展示管理。

### 核心价值
1. **便捷管理**：通过可视化界面管理用户、工具、作品，无需直接操作数据库
2. **操作安全**：管理员权限控制、二次确认、操作反馈，降低误操作风险
3. **高效运营**：批量操作、拖拽排序、图标选择，提升运营效率
4. **统一体验**：使用 Element Plus 组件库，提供专业的后台管理体验

## 权限控制

### 管理员标识

**数据库字段**：
- 用户表（`users`）增加 `is_admin` 字段
  - 类型：`Boolean`
  - 默认值：`false`
  - 说明：标识用户是否为管理员

**权限规则**：
- 只有 `is_admin = true` 的用户可以访问后台管理系统
- 普通用户（`is_admin = false`）无法看到后台入口，也无法访问后台页面
- 所有管理员权限相同，无细分权限（MVP阶段）

### 后台入口

**入口位置**：
- 管理员登录后，顶部导航栏右上角（退出按钮上方）显示"管理后台"入口
- 普通用户看不到此入口

**入口样式**：
- 文字链接或按钮："管理后台"
- 点击后跳转到后台首页（`/admin`）

**访问控制**：
- 前端路由守卫：检查用户是否为管理员，非管理员自动跳转到首页
- 后端API守卫：所有后台管理API检查用户是否为管理员，非管理员返回 403 错误

## 用户管理

### 功能概述

**核心功能**：
1. 用户列表（分页展示）
2. 创建新用户
3. 编辑用户信息
4. 删除用户（二次确认）
5. 重置用户密码
6. 设置用户为管理员

### 用户列表页面

#### 页面元素
- **页面标题**："用户管理"
- **操作按钮**："创建用户"（点击打开创建用户对话框）
- **用户列表表格**（使用 Element Plus Table 组件）：
  - 列：用户名、昵称、邮箱、手机号、是否管理员、创建时间、操作
  - 每行操作按钮：编辑、删除、重置密码
- **分页组件**（使用 Element Plus Pagination 组件）：
  - 支持切换页码和每页条数

#### 表格列定义

| 列名 | 宽度 | 说明 |
|:---|:---|:---|
| 用户名 | 自适应 | 显示用户的 `username` |
| 昵称 | 自适应 | 显示用户的 `nickname`，如果为空则显示"-" |
| 邮箱 | 自适应 | 显示用户的 `email`，如果为空则显示"-" |
| 手机号 | 120px | 显示用户的 `phone`，如果为空则显示"-" |
| 管理员 | 80px | 显示"是"或"否"，可以使用 Tag 组件（管理员显示蓝色标签） |
| 创建时间 | 160px | 显示格式：`YYYY-MM-DD HH:mm` |
| 操作 | 220px | 操作按钮：编辑、删除、重置密码 |

#### 操作按钮交互

**编辑按钮**：
- 点击后打开"编辑用户"对话框
- 对话框预填充当前用户的信息
- 用户可以修改用户名、昵称、邮箱、手机号、是否管理员
- 点击"保存"按钮，提交修改，成功后刷新列表并显示成功提示

**删除按钮**：
- 点击后弹出二次确认对话框："确定要删除用户 {username} 吗？删除后无法恢复。"
- 确认后，提交删除请求
- 删除成功后刷新列表并显示成功提示
- 删除失败显示错误提示

**重置密码按钮**：
- 点击后弹出"重置密码"对话框
- 对话框包含：新密码输入框（必填，最小6位）、确认密码输入框
- 点击"确认"按钮，提交重置密码请求
- 成功后显示提示："密码已重置为：{新密码}"
- 失败显示错误提示

### 创建用户功能

**触发方式**：点击"创建用户"按钮

**对话框内容**：
- 标题："创建新用户"
- 表单字段：
  - 用户名（必填，1-50个字符，字母/数字/下划线/中文）
  - 昵称（可选，1-50个字符）
  - 邮箱（可选，邮箱格式）
  - 手机号（可选，11位数字，以1开头）
  - 密码（必填，最小6位）
  - 是否管理员（复选框，默认不勾选）
- 底部按钮："取消"、"创建"

**表单验证**：
- 用户名：必填，格式验证
- 邮箱：如果填写，邮箱格式验证
- 手机号：如果填写，手机号格式验证（11位数字，以1开头）
- 密码：必填，最小6位
- 用户名/邮箱/手机号至少填写一个（用于登录）

**提交操作**：
- 验证通过后，提交创建用户请求
- 成功后关闭对话框，刷新用户列表，显示成功提示
- 失败显示错误提示（如"邮箱已被使用"）

### 编辑用户功能

**触发方式**：点击用户列表中的"编辑"按钮

**对话框内容**：
- 标题："编辑用户"
- 表单字段（同创建用户，但预填充当前用户信息）：
  - 用户名（必填）
  - 昵称（可选）
  - 邮箱（可选）
  - 手机号（可选）
  - 是否管理员（复选框）
  - **不包含密码字段**（密码通过"重置密码"功能单独修改）
- 底部按钮："取消"、"保存"

**提交操作**：
- 验证通过后，提交修改用户请求
- 成功后关闭对话框，刷新用户列表，显示成功提示
- 失败显示错误提示

### 边界条件与异常处理

**删除用户**：
- 不允许删除自己（当前登录的管理员）
- 删除用户时，系统检查该用户是否有关联数据（如会话、消息），如有则一并删除（级联删除）

**邮箱/手机号重复**：
- 创建或编辑用户时，如果邮箱或手机号已被其他用户使用，显示错误提示："该邮箱已被使用"或"该手机号已被使用"

**管理员数量限制**：
- 系统至少保留一个管理员（不允许删除或取消最后一个管理员的管理员权限）
- 如果尝试删除或取消最后一个管理员，显示错误提示："系统至少需要一个管理员"

|:---|:---|:---|

- 点击"下移"按钮，工具的 `order` 值加1，在列表中向下移动
- 排序操作实时生效，无需刷新页面

**切换可见性按钮**：
- 点击后切换工具的 `visible` 字段（`true` ↔ `false`）
- 切换后实时更新表格中的可见性状态
- 隐藏的工具不在前台工具卡片页显示

  - 图标（可选，图标选择器）
  - 排序（可选，数字，默认0）
- 底部按钮："取消"、"创建"

**表单验证**：
- 分类名称：必填，1-50个字符，不能与已有分类重复

**提交操作**：
- 验证通过后，提交创建分类请求
- 成功后关闭对话框，刷新分类列表，显示成功提示
- 失败显示错误提示（如"分类名称已存在"）

### 边界条件与异常处理

**删除分类**：
- 如果分类下有工具，不允许删除，显示错误提示
- 如果分类下没有工具，允许删除（二次确认）

**分类名称重复**：
- 创建或编辑分类时，如果分类名称已存在，显示错误提示："该分类名称已存在"

**HTML文件上传失败**：
- 文件大小超过5MB：显示错误提示："文件大小不能超过5MB"
- 文件类型不正确：显示错误提示："请上传HTML文件"
- 网络错误：显示错误提示："上传失败，请稍后重试"

## 图标系统

### 图标库

**使用图标库**：Heroicons（`@heroicons/vue/24/outline`）

**图标存储方式**：

### 图标选择器

**组件功能**：
- 展示所有可用的 Heroicons 图标（以网格形式展示）
- 支持搜索图标（按图标名称搜索）
- 点击图标后选中，选中的图标高亮显示
- 底部显示当前选中的图标名称

**使用场景**：
- 创建/编辑工具时选择图标

### 图标自动推荐

**推荐时机**：
- 用户创建/编辑工具、作品、分类时，如果没有选择图标
- 用户点击保存按钮时，系统根据名称或描述自动推荐一个图标

**推荐规则**（简单关键词匹配）：

```
关键词匹配逻辑（从名称和描述中提取关键词）：
- 包含"文档"、"Markdown"、"编辑" → document-text
- 包含"图表"、"统计"、"数据" → chart-bar
- 包含"代码"、"编程"、"脚本" → code-bracket
- 包含"表格"、"Excel"、"CSV" → table-cells
- 包含"计算"、"数学"、"公式" → calculator
- 包含"图片"、"照片"、"相册" → photo
- 包含"视频"、"播放"、"录制" → video-camera
- 包含"时间"、"倒计时"、"计时" → clock
- 包含"用户"、"分组"、"点名" → user-group
- 包含"二维码"、"扫码"、"QR" → qrcode
- 包含"教育"、"学习"、"课程" → academic-cap
- 包含"书籍"、"阅读"、"文库" → book-open
- 包含"创意"、"灵感"、"设计" → sparkles
- 无匹配：
  - 工具类型 → wrench
  - 作品类型 → photo
  - 分类类型 → puzzle-piece
```

**实现方式**：
- 前端或后端实现关键词匹配逻辑
- 匹配时忽略大小写，支持中英文关键词
- 如果匹配到多个关键词，使用第一个匹配结果
- 如果没有匹配到，使用默认图标

**用户体验**：
- 系统推荐的图标用户可以随时修改（编辑功能）
- 推荐逻辑尽量准确，但不要求完美（用户可以手动调整）

## 非功能性需求

### 安全性
- 所有后台API必须验证用户是否为管理员（`is_admin = true`）
- 非管理员访问后台API返回 403 错误
- 文件上传需要验证文件类型和大小，防止恶意文件上传
- HTML文件存储路径需要规范，防止路径遍历攻击
- 密码重置时需要验证操作者权限

### 数据完整性
- 删除分类时，如果有关联工具/作品，不允许删除（保护数据完整性）
- 删除用户时，级联删除其关联数据（会话、消息等）
- 系统至少保留一个管理员（不允许删除或取消最后一个管理员）

### 可扩展性
- 图标选择器设计需支持后续扩展更多图标
- 分类和工具的数据结构需支持后续添加更多字段（如权重、标签等）
- 后台管理系统的架构需支持后续添加更多管理模块（如AI工具管理、系统配置等）

### 可维护性
- 代码结构清晰，模块划分合理
- 使用 Element Plus 组件库，减少自定义组件的维护成本
- API设计遵循 RESTful 规范，便于前后端协作
- 前端路由、状态管理、API调用等逻辑分离，便于维护
