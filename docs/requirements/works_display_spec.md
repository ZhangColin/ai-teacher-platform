## 需求概述

### 背景
当前系统提供了"AI工具"、"教研员"、"常用工具"等功能模块。平台需要一个集中的作品展示空间，用于展示优秀的HTML作品成果，为用户提供灵感和参考。

### 目标
建立"作品展示"模块，为用户提供一个浏览和体验优秀HTML作品的平台。所有作品均为上传的独立HTML页面，用户可以在线预览和全屏体验。

### 核心定位
- **AI工具** - 基于大模型对话的生成类工具（文生文、图生成等）
- **教研员** - 教学研究与备课评课辅助工具
- **常用工具** - 日常工作中的实用小工具集合（编辑、转换、计算等）
- **作品展示** - 优秀HTML作品的展示平台（创意展示、灵感参考）

---

## 用户价值

### 目标用户
- 所有平台登录用户
- 寻找灵感的创作者
- 学习参考的学习者
- 希望了解平台能力的访客

### 核心价值
1. **灵感激发** - 浏览优秀作品，激发创作灵感
2. **便捷体验** - 无需下载，在线即可预览和体验作品
3. **集中展示** - 所有作品集中在一个平台，方便浏览和查找
4. **多样性** - 涵盖不同类型和主题的作品，满足不同兴趣

## 用户故事

### 故事1：浏览作品
**作为** 一名用户  
**我想要** 在作品展示页面浏览所有可用的作品  
**以便于** 快速找到感兴趣的作品并获得灵感

**验收标准**：
- 用户点击顶部导航"作品展示"，进入作品卡片页
- 作品按分类组织展示
- 每个作品显示名称、描述和图标
- 如果某个分类下没有作品，则不显示该分类

---

### 故事2：体验作品
**作为** 一名用户  
**我想要** 点击作品卡片后在线体验该作品  
**以便于** 了解作品的效果和创意

**验收标准**：
- 用户点击作品卡片，进入作品预览页面
- HTML作品在沙箱环境中运行（安全隔离）
- HTML页面占满作品详情页区域
- 页面提供"全屏"按钮，点击后进入全屏模式
- 全屏模式下提供"退出全屏"按钮
- 页面提供"返回"按钮，返回作品卡片页

## 功能详述

### 1. 作品卡片页

#### 页面结构
```
+--------------------------------------------------+
|  顶部导航栏（AI工具 | 教研员 | 常用工具 | 作品展示）|
+--------------------------------------------------+
|                                                  |
|  【分类1名称】                                    |
|  +----------+  +----------+  +----------+       |
|  | 图标     |  | 图标     |  | 图标     |       |
|  | 作品名称 |  | 作品名称 |  | 作品名称 |       |
|  | 作品描述 |  | 作品描述 |  | 作品描述 |       |
|  +----------+  +----------+  +----------+       |
|                                                  |
|  【分类2名称】                                    |
|  +----------+  +----------+                     |
|  | 图标     |  | 图标     |                     |
|  | 作品名称 |  | 作品名称 |                     |
|  | 作品描述 |  | 作品描述 |                     |
|  +----------+  +----------+                     |
|                                                  |
+--------------------------------------------------+
```

#### 交互行为
- **展示逻辑**：
  - 按分类组织作品，分类按预设顺序排列
  - 分类下的作品按预设顺序排列
  - 如果某个分类下没有作品，则不显示该分类
  
- **点击行为**：
  - 用户点击作品卡片，跳转到对应的作品详情页

- **视觉设计**：
  - 卡片布局、间距、hover效果等细节由前端团队设计
  - 要求简洁、大方、美观
  - 与常用工具模块保持一致的视觉风格

---

### 2. 作品详情页

#### 页面结构
```
+--------------------------------------------------+
|  [返回] 作品名称                   [全屏]         |
+--------------------------------------------------+
|                                                  |
|  +--------------------------------------------+  |
|  |                                            |  |
|  |        HTML作品内容（沙箱运行）             |  |
|  |                                            |  |
|  +--------------------------------------------+  |
|                                                  |
+--------------------------------------------------+

【全屏模式】
+--------------------------------------------------+
|                                      [退出全屏]  |
|  +--------------------------------------------+  |
|  |                                            |  |
|  |        HTML作品内容（沙箱运行）             |  |
|  |                                            |  |
|  +--------------------------------------------+  |
+--------------------------------------------------+
```

#### 功能要求
- **沙箱运行**：
  - HTML在iframe沙箱中运行，与AI工具预览面板的实现方式一致
  - 确保安全隔离，防止恶意代码影响主系统
  
- **布局**：
  - HTML页面占满作品详情页的内容区域
  
- **全屏功能**：
  - 提供"全屏"按钮，点击后HTML页面进入全屏模式
  - 全屏模式下提供"退出全屏"按钮
  - 全屏模式实现方式与常用工具的HTML工具保持一致
  
- **导航**：
  - 提供"返回"按钮，返回作品卡片页

## 非功能性需求

### 安全性
- HTML作品必须在沙箱环境中运行，防止XSS攻击
- HTML作品无法访问用户Cookie、LocalStorage等敏感信息
- HTML作品无法访问主系统的DOM结构

### 可扩展性
- 数据结构设计需支持未来的后台管理功能（上传、编辑、删除）
- 分类结构支持未来的动态管理
- 支持未来添加更多作品类型（当前仅HTML）

### 可维护性
- 作品渲染逻辑复用现有代码（AI工具预览面板、常用工具HTML工具）
- 代码结构清晰，与常用工具模块保持一致
- **独立实现**：虽然与常用工具功能类似，但采用独立的数据表、API、前端页面，支持两个模块独立演化

## 附录

### 设计参考
**作品展示模块的设计和实现完全参考常用工具模块**：
- 页面布局、交互方式、视觉风格保持一致
- HTML沙箱实现方式保持一致（参考AI工具预览面板）
- 全屏功能实现方式保持一致
- 分类和卡片的数据结构设计保持一致

**独立性说明**：
- 虽然功能和设计类似，但作品展示和常用工具采用独立的数据表、API端点、前端页面实现
- 两个模块可以独立演化，互不影响
- 未来两个模块可能朝不同方向发展（例如作品展示可能增加社交功能，而常用工具保持工具属性）

### 技术参考点
以下内容供架构师和开发团队参考，不属于产品需求范围：

1. **HTML沙箱实现** - 参考AI工具预览面板和常用工具的iframe沙箱机制
2. **全屏功能** - 参考常用工具的HTML工具全屏实现
3. **数据结构设计** - 参考常用工具的数据表结构，但使用独立的表和字段

### 当前阶段管理方式
- **作品上传**：管理员通过文件系统上传HTML文件到指定目录
- **数据录入**：管理员直接在数据库中录入作品信息（名称、描述、分类、HTML文件路径等）
- **分类管理**：管理员在数据库中维护分类数据
- **后台界面**：后续迭代与常用工具一起开发统一的后台管理界面
